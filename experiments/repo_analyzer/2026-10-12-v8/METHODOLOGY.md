# Методика benchmark v8

## Цель и scope

Проверяется `Repository snippets → technical observations + source locators` — промежуточный анализ GitHub-кода перед формированием `RepoEvidence`. Не исследуются авторство коммитов, достижения разработчика и финальная генерация резюме.

## Дизайн эксперимента

- 14 cases / 8 публичных репозиториев; dev 6 из трёх репозиториев, test 8 из пяти других.
- Основной semantic test — 7 code-backed cases / 4 repos, **34** выбранных эталонных факта (gold).
- Один test-кейс `sparse-converter` имеет только README; он исключён из метрик доказательств реализации. 59 gold-фактов всего по 13 кейсам (25 dev и 34 test).
- Семантическая разметка — 210 test claims шести локальных конфигураций (180 code-backed и 30 README-only). Нет независимой повторной проверки; это **предварительные оценки**.
- Все локальные модели выполнены на Colab Tesla T4; параметры контекста и генерации, источники и системный prompt приведены в [PROMPT_AND_SCHEMA.md](PROMPT_AND_SCHEMA.md).
- Оригинальный эксперимент имеет по одному выводу на модель/кейс: повторы не проводились.

## Эталон (gold) и сопоставление

Каждая gold-запись содержит атомарный факт, путь и диапазон строк исходного snapshot, repo/commit SHA и case_id. Gold фиксирует **выбранные инженерные факты**, а не абсолютно все технические подробности. Модель может выдать истинный факт вне gold: он входит в precision, но не увеличивает recall.

Для каждого claim оценивается `claim_label`:
- `supported`: всё утверждение подтверждается данным контекстом;
- `partial`: лишь часть составного утверждения подтверждается;
- `not_verifiable`: в контексте недостаточно информации;
- `contradicted`: исходник противоречит утверждению.

Отдельно проверяется `evidence_label`:
- `direct`: **указанные самой моделью** путь и диапазон прямо поддерживают весь факт;
- `partial`: указанная ссылка поддерживает только часть или недостаточно конкретна;
- `wrong`: нет файла, диапазон отсутствует в контексте или ссылается на неподходящий участок.

Утверждение может быть `supported`, но иметь `wrong` evidence. Дублирующиеся утверждения об одном gold-факте повышают число claims, но **не** количество покрытых gold.

## Метрики

Пусть:
- `N` = число разобранных model claims в 7 code test cases;
- `S` = число claims с `claim_label=supported`;
- `G` = число claims с `claim_label=supported` **и** `evidence_label=direct`;
- `K` = число уникальных gold_id, найденных истинными claims;
- `KG` = число уникальных gold_id, найденных grounded claims;
- `T=34` = размер gold на code test.

Тогда:
- `Claim Precision = S / N`
- `Grounded Precision = G / N` (**conditional on parseable outputs**)
- `Fact Recall = K / T`
- `Grounded Recall = KG / T` (**end-to-end**, включает ноль за неразбираемые ответы)
- `Grounded F1 = 2×GroundedPrecision×GroundedRecall / (GroundedPrecision + GroundedRecall)`
- `Unsupported Claim Rate = (not_verifiable + contradicted) / N`
- `Evidence Accuracy = direct_evidence / N` (отдельно от семантики)

Для полностью неразбираемого ответа не вычисляют precision как 100%; он не создаёт claims и даёт ноль найденных gold для end-to-end recall. Если `N=0`, conditional precision = N/A. Основная таблица — micro-average по claims и gold; кейсы принадлежат четырём разным test-репозиториям. Отдельный README-only кейс не входит в знаменатели.

## Структурные проверки

1. `json.loads(raw)`: чистый JSON.
2. Альтернативная, явно обозначенная оценка: удаляется только внешний блок `\`\`\`json` … `\`\`\``.
3. Схема: только `project_summary` и `observations`; в каждом наблюдении только `claim`, `category`, `source_path`, `line_start`, `line_end`.
4. Число наблюдений: 0–5 (ограничение валидатора).
5. Все файлы и диапазоны должны существовать **в предоставленных пронумерованных фрагментах**, включая промежуточные номера строк.

Эти проверки **не доказывают смысл claims**, потому что допустимый путь может вести к нерелевантному коду.

## Ограничения и интерпретация

- Небольшой выбранный gold и отсутствие независимой верификации разметки не позволяют называть один F1 статистически убедительной победой.
- Нет повторов, доверительных интервалов и строгой слепой разметки; сравнение пилотное.
- Разные модели могут получать другую распределённую «осторожность» (мало, но правильных claims), поэтому precision нельзя читать отдельно от recall и объёма.
- VRAM оценена на T4 при контексте 8192, **не** на GTX 1660 Super; замеры являются ориентиром аппаратной вместимости, не оценкой скорости другой карты.
- GitHub authorship/provenance и CV writing намеренно вне данной фазы.
- Существующая разметка с метаданными и evidence-текстом хранится без замены исходных полей; пересчёт агрегаций не пересматривает смысловые метки.

## Пересчёт

Из корня этой папки:

```bash
python scripts/recompute_semantic.py
```

Использует `annotations/gold_facts_ai.csv` и `annotations/claims_test_ai_annotated.csv`; без GPU и API. Таблицы `data/*.csv` и SVG — сохранённые агрегаты из того же эксперимента. Для новой независимой проверки качества необходимо заново оценить labels и повторить инференс с несколькими seed/запусками.
